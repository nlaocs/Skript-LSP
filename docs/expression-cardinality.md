# Expression input cardinality

`syntaxes::Expression::return_type_multiplicity_source` preserves optional SSG evidence that a registration delegates `isSingle()` to one `init(Expression[])` input. `expression_index` counts Java Expression slots, excluding regex slots, and includes null or omitted slots. Missing evidence remains unknown. Static `Both` remains the declaration that cardinality depends on input.

The native host checks the registration, definition, and implementation class against the catalog, and only creates a fact for a static `Both` registration with an explicit typed input and the supported evidence conditions. It maps the source slot to the exact capture index, then checks the successful parsed input. Groups and lists are inspected recursively; concrete complete types and native variables are accepted, while default/custom/unresolved inputs remain outside this proof. The resulting `host.expression.multiplicity-source` metadata has no addon owner and contains `{ "version": 1, "captureIndex": 0, "fullyParsedInput": true }`. Addons cannot replace this native fact with an unowned value.

CoreLibrary propagates only that input capture's summary cardinality. Single, Multiple, Both, and unknown are preserved. The generic handler targets the PropertyExpression and SimplePropertyExpression families and requires positive metadata; the family alone proves nothing. Existing semantic handlers can also use the evidence. Other unhandled superclass families keep their prior behavior even when the public catalog exposes source evidence. No WIT or ABI change is required, and third-party native parser environments may consume the model directly.

The normal regressions use the saved complete snapshot and raw returned-object observations in `utilities/skript-repl/tests/corpus`; they do not need Java, Skript, or a Minecraft server. The 25 controls compare single/AND/OR operands, nested functions, scalar/list arguments, and rejected plural scalar arguments. They enforce selected classes/patterns/registrations, nested types/cardinality, capture positions, and function argument ownership where the observer exposes them. The original 36 cases and their identity/capture/diagnostic projections remain covered.

These are partial comparisons. The three world/yaw/pitch fields in the research teleport now require observed Single rather than accepting Both as a known difference. The existing 16 ClassInfo/runtime implementation fields remain explicitly unnormalized. The default-world control still has native Both versus observed Single because the source proof requires explicit input. The lore one-to-many control has observed Multiple and native unknown; it prevents an unconditional Single fallback. Physical conversions, missing observer adapters, default source identity, and positional-versus-NAMED API normalization remain unknown. This slice does not certify a complete object graph or general upstream compatibility.
