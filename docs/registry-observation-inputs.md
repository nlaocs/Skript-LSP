# Registry observation input preparation

The full strict observation/projection validator remains covered by real Core and
reflect fixtures. Activating that entire check in one Structure hook exhausted
the unchanged 20M fuel, including after direct typed decoding. It is **not adopted
as the production v1 validation path** and Player storage recovery is not claimed.

Production first reads a bounded eligibility header. Current observation v1
declares boundary-only generation and carries no authenticated producer domain.
It is therefore Ineligible + DetailsDeferred before full validation begins.
No Types/EventValues/Operations detail work is requested for this ineligible path.
Ignored detail arrays are not called valid, complete, or identity-checked. A getter
is runtime-unvalidated; an offline hidden-getter finding is not copied into a
runtime certificate. Explicit incomplete claims remain separately identified.

Any explicit observation stops legacy authorization until a supported complete
proof path exists. Old snapshots without observations retain their separately
audited legacy model. A header alone never issues a storage result, provenance
seal or private context receipt. This is a stability checkpoint, not completion
of mixed-environment storage certification.

The private Manifest token is created only by a fixed host Catalog reader.
Reads use64KiB chunks, a2MiB raw Manifest ceiling and at most64advancing calls,
checking offset/total/source before and after every chunk. The host's immutable
full raw-source digest covers every filename/length/byte, including unknown
Manifest fields. No arbitrary bytes/callback can create this token in production.
Standalone byte validation retains its independent SHA path. Read/transport/
cancellation/source failures do not become permanent negative cache entries.

The512KiB SSG observation export budget is separate from the Manifest ceiling.
Neither it nor the20M fuel ceiling is increased by this change. The experimental
1/2/4MiB and full-projection results must not be described as all accepted or as
physical editor latency. Future larger useful proof data needs bounded preparation
at source load, with source/component/schema ownership and revision binding;
it must not repeat whole validation in each hook or promote source integrity into
Java producer authority. External addon raw Catalog access remains unchanged.
